为何 fork 只支持 arm64:寄存器决定了 TLS 形态
go tool dist list 里 openharmony 只有 arm64,差异源自架构本身
arm64 (aarch64)　支持
MRS TPIDR_EL0 硬件指令直接读线程指针
有空闲寄存器可常驻存放 goroutine 指针 g
几乎不触发会引发 IE 重定位的那种 TLS
✓ 真机直接点亮,完整链路跑通
amd64 (x86_64)　不支持
没有空闲寄存器可存 g
访问 g 必须走 FS:偏移 的 IE / GOT TLS
正是 musl 拒绝的那种形态;需完整移植 amd64 TLSDESC 后端(PR #75048,未释出)
✗ 模拟器(x86_64)这条路走不通
苦涩的结局:本机是 x86_64 主机 —— 连 arm64 模拟器都开不出来。回到开头「先确认模拟器架构」那步的 x86_64,最终决定了模拟器走不通。
